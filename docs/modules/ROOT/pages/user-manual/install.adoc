= Install and lay out the application
:description: Add rdf-persistence and its generator to an application and lay out where the model and the generated code go.
:page-revised: 2026-11-10 by the developer

_How do I start an application?_

This page adds rdf-persistence to an application's `pyproject.toml` and sets out the folders the
rest of the manual uses. Afterwards `uv sync` has installed the library, the `rp-generate` command
and the testkit, and you are ready to xref:user-manual/model.adoc[write the model].

[#dependencies]
== Add the dependency

rdf-persistence is installed from its `develop` branch. The generators are needed at build time
only, so they go in the dev group, together with the test helpers:

[source,toml]
----
# pyproject.toml
[project]
name = "library"
version = "0.1.0"
dependencies = ["rdf-persistence"]

[dependency-groups]
dev = ["rdf-persistence[generate,testkit]", "hypothesis", "pytest"]

[tool.uv.sources]
rdf-persistence = { git = "https://github.com/meaningfy-ws/rdf-persistence", branch = "develop" }
----

The generator is the package `rdf_persistence_generation`. It ships in the same `rdf-persistence`
wheel, so there is nothing else to install. The two extras add only third-party libraries: `generate`
adds LinkML, which generating needs, and `testkit` adds the container libraries of the testkit's
integration fixtures.

Run `uv sync`. The `rp-generate` command and the freshness plugin are always installed. Generating
(`rp-generate`) needs the `generate` extra: without it, the command exits with code 2 and says so.
`rp-generate --check` and the freshness plugin need no extra: without it they only compare the
manifests (xref:user-manual/generated-classes.adoc#guard[Guard the model in your tests]).
Upgrading from a version before 0.5.0? See xref:user-manual/change-model.adoc#upgrade-generator-package[Upgrading to the generator package (0.5.0)].

== Lay out the application

_Where do the model and the generated files go?_

[source,text]
----
models/                       the LinkML schema: a root schema and one file per module
library/domain/generated/     generated Python, shapes, context and frames (never edited)
library/services/             your domain services
library/entrypoints/          your composition root and routes
web/src/domain/generated/     generated TypeScript types (never edited)
docs/model/                   generated diagrams, one per module
tests/
----

The domain services are the subject of xref:user-manual/store-and-read.adoc[Store and read
aggregates], the composition root of xref:user-manual/serve.adoc[Serve the application]. Every
example in this manual uses these paths; `rp-generate` takes them from its configuration
(xref:user-manual/generate.adoc[Generate the code]).

Generated files go only in folders named `generated`, except the diagrams, which the file guard
does not look at. The guard fails on shapes, contexts, frames, JSON schemas, OpenAPI files or
`.ts` files (other than `*.test.ts` and `*.spec.ts`) found elsewhere in the folders you give it
(xref:user-manual/generated-classes.adoc#guard[Guard the model in your tests]).
