== Purpose and origin

*Built for* a stateless mapping layer between Pydantic models and RDF triples: declare subject IRIs, literals, lists, language tags, nested resources and named graphs once, then move data between models, local graphs and RDF files.

*Who and in which context.* A single author (GitHub `eddiethedean`), the same as sparqlmodel, which builds on it.
Twelve minor releases between 2026-05-17 and 05-22, driven by a roadmap with one exit-criteria script per milestone.
It started on rdflib, switched to pyoxigraph only in 0.10 (reason not stated) and removed SHACL in 0.11.
Its examples (Nobel, DCAT, Wikidata) show a data-wrangling and ETL angle next to the application one.

*Design angle.* Mapping-first and stateless: "We do not build sessions, query compilers, or cascade `put` semantics" (`docs/ROADMAP.md:20, 42`). Engine-centric, file- and local-graph-oriented, model in code.

*Where it fits.* L1 mapping, with partial L0 and L2. As a dependency it fits nowhere: it fails DEC-5, conflicts with DEC-4 (no rdflib) and has no remote store.
As an idea source it fits our mapper internals (approach A) and is an easy template target for approach B.

== How it works

*Mapping.* A `TripleModel` subclass declares a nested `class Rdf` (namespace, `type_uri`, `id_field`, prefixes, embed mode, `graph_iri`).
Fields use `rdf_field(predicate)` or `Annotated[..., Predicate(...)]`; metadata sits in Pydantic `FieldInfo` (`model.py:69`).
Predicates are validated when the class is defined. A subclass `Rdf` *replaces* the parent's instead of merging (`model.py:47–49`).

*Identity.* `subject_uri = namespace + percent-encode(id_field)`; full `http(s)://` or `urn:` values pass through (`config/rdf_config.py:24–34, 106–130`).
Minting is deterministic and reversible (`id_from_subject_uri`). No UUID default.

*Export.* `python_to_term` plus a `LiteralRegistry` (Decimal, UUID, Enum, gYear …) converts values (`terms/registry.py:19–163`).
`set[T]` gives repeated objects; `list[T]` gives an `rdf:List`. Nested models embed by IRI or blank node through strategy objects (`embed/strategies.py:19–134`).

*Write modes.* `add` appends. `replace` clears nested children and removes *owned* triples (mapped predicates plus type), then adds. `patch` resets per subject and predicate (`io/sync/modes.py:54–216`).
Foreign predicates survive (test `test_replace_preserves_unowned_triples_on_subject`).

*Import.* `graph_to_model` collects owned predicates, applies `strict_import` / `warn_unmapped_fields`, handles duplicates, resolves inverses, and ends in `model_validate` (`io/import_.py:493–623`).
`rdf:type` dispatch can follow `rdfs:subClassOf` (`io/dispatch.py`, `io/rdfs.py`).

*Named graphs.* `Rdf.graph_iri` or `graph_iri=` places a model in a named graph of a local `Dataset`; TriG and N-Quads I/O (`io/dataset.py:152–245`).

*Store and SPARQL.* Since 0.10 the graph is its own `RdfGraph` facade over `pyoxigraph.Store`, copying rdflib idioms (`store/graph.py:53`).
SPARQL runs on the local store only; `initBindings` uses pyoxigraph substitutions (`io/sparql.py:243–270`), except ASK, where terms are inlined into the query text (`io/sparql.py:110–124`).
Remote access is gone: `open_sparql_graph` raises, so `load_sparql` always raises (`io/sparql.py:666–731`).
`store_rollback` is an explicit no-op (`io/stores.py:121–131`).

*Serialisation.* pyoxigraph formats, JSON-LD included (`store/formats.py:24–68`). JSON-LD contexts only raise a warning, so output is expanded or flat (`store/io_warnings.py:52, 77, 84–88`).

*Codegen.* `triplemodel-codegen` reads OWL/RDFS and emits stub classes (`codegen/parse.py`, `codegen/emit.py`, 124 LOC). Labelled experimental.

== What to borrow

* *Write modes as named strategies* (add / replace / patch) with owned-predicate semantics: clear only mapped predicates and `rdf:type`; foreign triples survive (`io/sync/modes.py`, `io/sync/predicate_ops.py`).
* Deterministic IRI minting `namespace + quote(id)` with a reversible inverse and pass-through for full IRIs.
* `set[T]` for repeated values versus `list[T]` for `rdf:List`, expressed purely by typing.
* `LangString` / `MultiLangString` value types and a pluggable `LiteralRegistry` (`register_literal_type`, `terms/registry.py:134`).
* `BackPopulates` paired inverses validated at class definition (`fields/back_populates.py:169–299`); `OntologyRegistry` hints.
* Per-class named-graph placement, overridable per call.
* Strict or warn-on-unmapped import, skolemisation policy, CBD extraction (`io/cbd.py`), graph and model diff (`io/compare.py:46–127`).
* Precise errors, e.g. `Rdf.namespace is required to derive a subject IRI; set it on the model's Rdf class or pass uri= explicitly.` (`config/rdf_config.py:107–111`).

For our LinkML route the same metadata should come from `class_uri` / `slot_uri`, not a hand-written `class Rdf`.

== What to avoid

* *Advertised but dead API.* The README lists `load_sparql`; it always raises `NotImplementedError` (`io/sparql.py:666–731`).
* *Silent no-op transactions.* `store_rollback` does nothing (`io/stores.py:128–131`).
* *Broken stability claim.* "Public API frozen from 0.9" was followed by breaking 0.10 and 0.11.
* *Re-implemented rdflib.* `RdfGraph` copies rdflib idioms; for ASK queries `initBindings` is emulated by inlining terms into query text (`io/sparql.py:110–124`). That path inlines terms by regex without escaping quotes (`io/sparql.py:96–124`): an injection risk.
* *Active Record leakage.* `to_graph`, `parse_url`, `serialize`, `construct_from_sparql` on the domain class.
* *Inheritance footgun.* A subclass `Rdf` replaces the parent config (`model.py:47–49`).
* *Lossy import by default.* Single-valued fields keep the first value (a `UserWarning`, configurable to an error, `io/import_.py:102–112`); `jsonld_context` is accepted and ignored.
* *Claimed, not found in code:* JSON-LD context support (`Rdf.jsonld_context` only warns); SHACL (ROADMAP 0.4, removed in 0.11); real store transactions (`store_rollback` exists as an API but is a documented no-op, `docs/ROADMAP.md:115`; callers get no runtime signal).
* Stale RTD landing page ("SparqlModel … planned but not yet available").

== Authorization seams

* *ACL-agnostic by construction, trivially.* It never talks to an endpoint; it maps to and from a local graph. `fetch_url` is an unauthenticated urllib GET (`io/files.py:199–206`).
* *Where a PEP would go.* In whatever moves the local graph to and from the remote store: a store adapter in rdf-persistence, or sparqlmodel's `HttpStore`. triplemodel offers no hook.
* *Graph placement.* `Rdf.graph_iri` works only inside a local `Dataset`. If an adapter emitted `GRAPH <g>`, a rewriting proxy would override it, so placement must stay advisory (DEC-8, A2).

== Code-generation fit

*Feasible, arguably easier than for sparqlmodel*, because the mapping is static configuration:
`class Rdf` ← `class_uri`, `id_prefixes` and schema `prefixes`; `rdf_field(slot_uri)`; `ref_field` versus nested model ← `inlined`; `set[...]` ← `multivalued`; `LangString` ← language slots; `Rdf.graph_iri` ← an annotation.

Gaps for a generator:

* Entities must subclass `TripleModel`; stock `gen-pydantic` output needs a custom template.
* A subclass `Rdf` replaces the parent's, so every class needs a full, flattened `Rdf`.
* `structured_pattern` minting needs generator logic; full-IRI and CURIE identifiers fit.
* Enums with `meaning:` IRIs need custom mapping.
* No SHACL: LinkML shapes must be validated with pySHACL on an rdflib graph, which needs a format round-trip.

== Final verdict

*Ideas.* Borrow the mapping semantics; never depend on it.

. It is *only a mapper over a local pyoxigraph graph*: no remote SPARQL (`load_sparql` always raises), no session and no real transactions (`store_rollback` is a no-op).
. It *left rdflib* for its own facade, so it cannot interoperate directly with pySHACL, the LinkML runtime or SPARQLWrapper; this conflicts with DEC-4.
. Its reusable value is the *mapping semantics*: owned-predicate write modes (add / replace / patch), reversible IRI minting, `set` versus `rdf:List`, `LangString` and the literal registry, strict import and per-class graph placement. Re-express them over LinkML `class_uri` / `slot_uri` metadata with inheritance-safe config.
