== Purpose and origin

* *Built for:* letting Pydantic v2 users load and dump RDF with the model they already have ("seamless bidirectional conversion between typed data models and semantic web data", README).
* *Who and when:* one author ("Omegaice"), 2025. Two releases (0.1.0, then 0.2.0 on 2025-05-02), then dormant. No institution is named.
* *Design angle:* a codec, not an ORM. It stops at the `rdflib.Graph` boundary and leaves validation and JSON Schema to Pydantic. The mapping sits on the model through a base class plus `Annotated` markers: Active-Record-style coupling, convenient for hand-written models.
* *Where it fits:* L1, as a design donor for our Graph-to-object codec (M7 predicate defaults, `WithPredicate`, `PydanticURIRef` for G5); not its base-class coupling. LinkML 1.10.0 `gen-pydantic` already emits `linkml_meta` with `class_uri` / `slot_uri`, so our codec can read that instead of requiring `BaseRdfModel`. It fails DEC-5 (23 stars, no commit in 12 months): ideas only, or vendoring under MIT.

== How it works

*One class.* `BaseRdfModel` does everything: type introspection, field extraction, parsing, serialisation (`model.py:40–389`).

*Mapping.* A field's predicate is `WithPredicate.extract(field)` or, by convention, `cls._rdf_namespace[field_name]` (`model.py:53–61`).
The class-level `rdf_type` is checked strictly on parse; a missing `(uri, rdf:type, rdf_type)` raises `ValueError` (`model.py:283–284`).
No subclass dispatch: `all_entities` matches the exact type (`model.py:320–322`).

*Identity.* `uri: PydanticURIRef` is required (`model.py:49`); no minting, no blank nodes (`model.py:188, 321`).
Parsing keeps a per-call `(cls, uri)` cache with an `_IN_PROGRESS` sentinel. On a cycle it *raises* `CircularReferenceError` (`model.py:192–193, 270–299`).

*Relationships.* A nested model (or `Self`) is a reference: its `uri` is emitted and its graph merged (`model.py:376–380`). `list[Model]` gives 1-n as repeated triples, unordered (`model.py:363–369`).
Eager only; serialisation cascades the whole reachable tree.
`model_dump_rdf` recurses into nested models without a visited set (`model.py:368, 380`), so a cyclic object graph presumably recurses until a `RecursionError` (not verified by running): cycles fail on both read (`CircularReferenceError`) and write.

*Literals.* Writes use bare `Literal(value)`, so rdflib infers the datatype (`model.py:373, 387`). `dict` becomes a JSON-string literal (`model.py:383–385`).
Reads use `Literal.toPython()` (`model.py:199`), which drops language tags.
`WithDataType` is exported and documented but never read (`annotation.py:41–60`).

*Flow.* `parse_graph → _extract_field_value → graph.objects → _convert_rdf_value → (nested parse_graph | toPython) → model_validate` (`model.py:296`).
`model_dump_rdf()` builds a new Graph each call (`model.py:336`); storing is the caller's `graph += ...`.

*Schema.* `PydanticURIRef` is `Annotated[URIRef, URIRefHandler]` with a core schema that coerces strings and emits JSON Schema `{"type":"string","format":"uri"}` (`types.py:24–62`).

== What to borrow

* `Annotated[...]` markers for predicate (and datatype, honoured this time) metadata (`annotation.py:6–38`).
* Namespace-plus-field-name predicate defaults with per-field override (`model.py:53–61`).
* The `PydanticURIRef` core-schema type: an IRI that validates and shows as `format: uri` in JSON Schema (`types.py:24–62`).
* The `(cls, uri)` hydration cache.
* The policy-free codec shape: the codec never touches a store, so enforcement can sit in the store port or proxy.

Keep the mapping in an external mapper or registry keyed by LinkML `class_uri` / `slot_uri`, not on a `BaseModel` subclass, so generated domain classes stay persistence-free.

== What to avoid

* *Silently ignored public API.* `WithDataType` is exported and documented but never read (`annotation.py:41`). *Claimed, not found in code.*
* *Circular references:* the README and docs say they are supported; parsing raises `CircularReferenceError` and the test expects it (`model.py:193`). *Contradicted by code.*
* *Silent data loss:* language tags dropped on read (`model.py:199`); a single-valued field takes the first of several values (`model.py:245`); `WithDataType` ignored (`annotation.py:41`); `dict` stored as an opaque JSON string. Ignoring unmapped predicates on parse is normal codec behaviour, not data loss.
* *Unordered lists:* `list[T]` becomes repeated triples.
* *Global type coupling:* `arbitrary_types_allowed=True` on every subclass (`model.py:43`).
* `_rdf_namespace` is a private-looking name the user must set; a doc bug imports `Annotated` from `pydantic`.

== Authorization seams

* *Fully ACL-agnostic by construction.* The library never touches a store. The caller fetches a Graph (e.g. a CONSTRUCT through an authorizing proxy) and hands it to `parse_graph`; whatever the proxy filtered is what gets hydrated.
* *PEP sites:* before the call, where the Graph is obtained; field level through Pydantic serialisation options (`exclude`, custom serialisers) at the API boundary; write side by checking the triples from `model_dump_rdf()` before sending.
* *Verdict:* a clean seam by absence; the right shape for a codec in rdf-persistence.

== Code-generation fit

*Good, with template work.* `gen-pydantic` already emits Pydantic v2 classes. A custom template would:

. change the base from `ConfiguredBaseModel` to `BaseRdfModel`;
. emit `rdf_type = <class_uri>` and `_rdf_namespace = <default_prefix>`;
. emit `Annotated[..., WithPredicate(<slot_uri>)]` per slot;
. map the LinkML `identifier` slot to the mandatory `uri`.

Not honoured even then: `is_a` dispatch, `langString` and datatype ranges, `inlined` versus reference, ordered multivalued slots.
*`linkml_meta` (verified against LinkML 1.10.0).* `gen-pydantic` defaults to `metadata_mode=auto` (`pydanticgen.py:316, 939–940`). It emits `linkml_meta: ClassVar[LinkMLMeta]` per class (`templates/class.py.jinja:14`) and `json_schema_extra={"linkml_meta": ...}` per field (`templates/attribute.py.jinja:18`), keeping `class_uri` and `slot_uri`.
So an external mapper can read the mapping from persistence-free generated classes, with no base class.
Caveat: the default metadata mode (`--meta auto`, still the default in LinkML 1.12) drops `range`, `inlined`, `inlined_as_list`, `multivalued`, `required`, `identifier` and the cardinalities (`template.py:191, 260`). They return with `metadata_mode=full` (CLI `--meta full`) or `except_children`. A runtime mapper must not infer them from the Python annotations alone (a reference slot becomes a bare `str`); generate with full metadata and check it at build time (G33).
Not verified: whether an *implicit* `class_uri` (derived from `default_prefix`) is materialised.

Only the `Annotated` markers fit the persistence-free pattern. pydantic-rdf itself requires every class to subclass `BaseRdfModel` and declare `rdf_type` / `_rdf_namespace` (`model.py:40–49`), and the parse and dump methods live on the domain class (`model.py:249, 325`).

== Final verdict

*Ideas.* MIT and small enough to vendor the `PydanticURIRef` type; do not take it as a dependency (fails DEC-5, dormant since 2025-05).

Three things to remember:

. *Its base-class coupling is the wrong shape for approach A.* Read the mapping from LinkML `linkml_meta` on persistence-free generated classes instead. LinkML emits `class_uri` / `slot_uri` by default (`--meta auto`, LinkML 1.10 to 1.12) but drops `range`, `inlined`, `multivalued`, `required` and `identifier`; generate with `metadata_mode=full` (or `except_children`) and check completeness at build time (G33).
. *Round-trip fidelity is the hard part a codec must get right, and pydantic-rdf does not:* language tags, datatypes (`WithDataType` inert), extra values for single-valued fields, list order and cycles are silently lost or fail. Our codec needs round-trip property tests on exactly these.
. *"Policy-free codec" is the right authorization shape for L1:* the converter never touches a store, so enforcement lives in the store port or proxy and the codec stays ACL-agnostic.
