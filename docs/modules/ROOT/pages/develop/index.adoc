= Working on the library
:description: How to change rdf-persistence itself: the package layout, the Make targets, hand-written types, container tests, how long the checks take, releases and what to run before a PR.

This page is for developers changing rdf-persistence itself. To set up a machine (uv, pre-commit,
Docker), follow `INSTALL.md` at the repository root. Changing the generator or the toolkit's own
schemas is on xref:develop/generator.adoc[Working on the generator]. Why the toolchain works this
way is explained in xref:architecture/generation.adoc[Model to code].
What is specific here when agents carry out the work is on
xref:develop/agents.adoc[Working with agents]; every test follows the
xref:develop/testing.adoc[testing checklist].

== The one rule

LinkML is the single source of specification
(xref:architecture/open-decisions.adoc[D-13]). Every model artefact (classes, enums, shapes,
JSON-LD context and frames, TypeScript types, diagrams) is generated. To change one, change the
schema and run `make generate`. Never edit a file under a `generated/` folder by hand: the freshness
check rejects it. Plain data records of the toolchain and the testkit are generated too. Hand-written
types are allowed only where a field holds a run-time object LinkML cannot express (see
<<hand-written>>).

The layers import downward only: `entrypoints | adapters > services > domain`.
`make check-architecture` enforces this.

== Make targets

_Which tests do I run while developing?_ Three lanes, from the quickest: `make test-changed` while
you work (the tests of what you changed, a few seconds to a minute), `make test-fast` when you are
unsure what a change reaches (about 6 to 10 min), and `make check-all` once before the PR. How a test
earns the `slow` mark, which keeps it out of `make test-fast`, is on
xref:develop/testing.adoc#slow[the testing checklist].

[cols="2,4",options="header"]
|===
|Target |Use it to
|`make install` |Install every dependency group and extra (`uv sync --all-extras`)
|`make generate` |Regenerate every `+[[tool.rp-generate]]+` entry of this repository and the toy library
|`make check-freshness` |Run `rp-generate --check` on both projects: lint, checks, and the manifest comparison
|`make check-generated` |Regenerate from scratch and fail if anything differs from what is committed
|`make refresh-snapshot` |Rewrite `tests/fixtures/model-shape.yaml` after a deliberate model change; it leaves the public-surface baseline alone
|`make refresh-surface` |Rewrite `tests/fixtures/public-surface.json`; this resets the baseline that guards the public surface of the thematic move (TC-03), so run it only when a stage deliberately moves a public name, and review the diff
|`make refresh-golden` |Rewrite the golden folders of the extensions' schemas that are not the toy; it leaves the served goldens alone
|`make refresh-served-golden` |Rewrite the served OpenAPI and TypeScript goldens (`tests/fixtures/library/golden/openapi`, `served_typescript`); this resets the baseline that guards the thematic move, so review the diff
|`make test` |Run the unit, feature and generator lanes (`make test-unit`, `make test-feature`, `make test-generator`), each in parallel (`pytest -n auto`) with its coverage floor
|`make test-changed` |Run only the tests of the files you changed against `develop` (`BASE=` and `PYTEST_N=` override the base and the worker count); the lane for every task
|`make test-fast` |Run every unit and feature test not marked `slow`, without coverage; the fallback of `make test-changed`
|`make profile-tests` |Print the 15 slowest unit and feature tests, set-up and call apart; `PROFILE_MARK` narrows the selection
|`make test-unit`, `make test-feature` |Two of the three lanes of `make test` (the third is `make test-generator`), each in parallel over the library; coverage floors 80 % (unit) and 50 % (feature)
|`make test-generator` |Run the generator's unit, feature and integration tests of `tests/generator/` in parallel, without containers; fails under 80 % coverage of `rdf_persistence_generation`; needs Node 20 for the `tsc` test, which the CI job `test-generator` sets up
|`make test-perf` |Run the wall-clock budget tests alone (needs Docker); not part of `check-all` or CI
|`make refresh-map` |Re-key the rows of `tests/audit/scenario-map.csv` whose test file was renamed (against `BASE`, default `develop`, or an explicit `--moved OLD=NEW`), drop those whose test is gone and list the collected tests that have no row (exit 1 while some are unmapped); keeps the map when the collection fails
|`make mutation` |Mutate the domain layer of every theme (`rdf_persistence/*/domain/*`, without `generated`), `iris/services/iris.py` and `tenancy/services/tenant_move.py` (`mutmut`, selection in `setup.cfg`: `tests/unit/core`, `tests/unit/files`, `tests/unit/iris` and `tests/unit/tenancy/test_tenant_move.py`) and print the killed, survived and untested counts; slow, not part of `check-all` or CI
|`make test-containers` |Run the integration and e2e tests against Fuseki, Garage, Zitadel and Redis (needs Docker); local only, not in CI
|`make fuseki-image` |Load the Fuseki test image from `temp/fuseki-image.tar`; build it and save the tar first when the tar is missing or older than `fuseki/` or `compose.yaml`
|`make format`, `make format-check` |Format the code with Ruff, or only check it (`check-quality` runs the check)
|`make check-style`, `make check-types`, `make check-architecture`, `make check-spec-docs`, `make check-generation` |The check groups; CI runs each as its own job, in parallel, with `test-unit`, `test-feature` and `test-generator`. Containers, e2e and Fuseki never run in CI
|`make check-quality` |Every check group except `check-generated`: style, types, architecture, spec and docs, freshness
|`make check-all` |`check-quality` and `test`: run it before every PR
|`make check-docs`, `make build-docs` |Check and build these docs
|===

[#hand-written]
== Add a hand-written type

Only two kinds of type are written by hand:

* a type whose field holds a foreign run-time object (a `SchemaView`, a callable, an rdflib graph);
* a subclass of a LinkML generator or template class.

The model guard fails on any other `BaseModel`, `RpModel`, enum, `TypedDict`, `NamedTuple` or
dataclass outside a `generated` folder. Add a type of the first kind to `HAND_WRITTEN` in
`tests/unit/testkit/test_model_guard.py`, as `"<path>:<ClassName>"`, with a one-line comment
saying which foreign object it holds. A test fails if an entry no longer exists. A generator
subclass is not flagged, so it needs no entry.

== Container tests

Tests under `tests/integration/store/`, `files/` and `identity/` get the markers `store`, `files`
and `identity` from their path, and run only with `make test-containers`. The containers are
defined in `rdf_persistence/testkit/containers/compose.yaml`; each has a smoke test that starts it
and checks it answers.

[#release]
== Cutting a release

Releases are proposed by release-please from the Conventional Commits on `develop`; a person
reviews and merges them. Nobody edits the version by hand: it lives in `pyproject.toml` alone, and
`rdf_persistence.__version__` reads it from the installed package.

. After a `feat`, `fix`, `perf` or `revert` commit (or any commit marked breaking) lands on
  `develop`, the `release` workflow opens or updates one PR, "chore(develop): release X.Y.Z". Its
  body holds the release notes. Commits of other types alone open no PR.
. Before 1.0.0 a breaking change and a `feat` bump the MINOR, and a `fix` or `perf` bumps the PATCH.
  To declare 1.0.0, add a `Release-As: 1.0.0` footer to a commit on `develop`; the bump rule never
  does it.
. Open a PR into `develop`, `docs(changelog): release X.Y.Z`, that renames `[Unreleased]` in
  `CHANGELOG.md` to `[X.Y.Z] - YYYY-MM-DD`, adds an empty `[Unreleased]` above it, and updates the
  two compare links at the foot. Do not commit on release-please's own branch: it rebuilds that
  branch on every push to `develop`. It gets no CI run (`ci.yaml` ignores `*.md`), so merge it
  after review; the release PR refreshes.
. Review the release PR (the version and the notes against the CHANGELOG) and merge it. The PR
  gets no CI run of its own, because a PR made with the workflow token starts no workflow;
  `ci.yaml` runs on the merge commit.
. The merge tags `vX.Y.Z` and creates the GitHub Release. The `build` job then builds the wheel
  and sdist with `uv build`, checks that the wheel carries `X.Y.Z` and imports in a clean
  environment, and attaches both to the Release.
. Once `build` is green, fast-forward `main` to the release, by hand:
+
[source,bash]
----
git fetch origin --tags && git push origin "vX.Y.Z^{commit}:refs/heads/main"
----
+
Never add `--force`. If git refuses, `main` holds a commit that is not in the release: find out who
moved it before doing anything else. If GitHub refuses for a missing `workflows` permission or a
branch rule, push with a credential that may update workflow files, or ask the developer to relax
the rule.
. If the release PR left the root version in `uv.lock` unchanged, open a `chore: uv lock` PR into
  `develop`. A stale lock is only noise: CI runs `uv sync` without `--locked`.

A failed `build` is fixed forward with a new PATCH release; never move or re-create a tag. There is
no PyPI yet: consumers install the `develop` branch, or pin a release with `@vX.Y.Z`.

== Before a PR

* `make check-all` passes. `make test-containers` passes as well if you touched adapters or
  containers.
* Generated code and its schema are in the same commit, and `make check-generated` shows no diff.
* The commit cites the change and task (`Refs: toolkit-v1-foundation 1.19`).
* The PR targets `develop`.
