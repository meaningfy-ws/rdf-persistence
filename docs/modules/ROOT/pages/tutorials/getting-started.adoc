= Getting started
:description: A first walk with rdf-persistence: model a book in LinkML, generate its code, store a book and read it back.

In this tutorial you build the first step of the toy library, the application the whole
xref:user-manual/index.adoc[user manual] is written around. You write a model with one aggregate,
`Book`, generate the code, store one book and read it back. It runs in memory, so you need no
triple store, no identity provider and no Docker. It takes about ten minutes.

The application is in the toolkit's repository, under
`docs/modules/ROOT/examples/getting-started/`. It is a cut of the toy library in
`tests/fixtures/library/`: the names, IRIs and descriptions are the toy's, and a test checks that
every class and slot of the example is defined identically there. The test also runs the
application against the toolkit's current code on every change, so the page and the code move
together.

You need Python 3.12 and https://docs.astral.sh/uv/[uv].

== 3. Generate the code

Tell `rp-generate` where the schema is and where the code goes:

[source,toml]
----
include::example$getting-started/pyproject.toml[tag=generate]
----

Add it to the same `pyproject.toml`, then run it:

[source,shell]
----
uv run rp-generate
----

It checks the model, then writes the Python classes, SHACL shapes, a JSON-LD context and the
OpenAPI components into `domain/generated/`, and the schema lock into `migrations/`. It prints
`generated 1 target(s), no problems`. You never edit what it writes: change the model and run it
again.

== What happened

* `kit.tenancy.create` made a database for the library, stored its root object and an access
  record that grants Ada the `librarian` role (`creator_role` in the settings) on it. Nothing
  here defines what that role may do, and a session checks no rights: the access rules apply to
  the HTTP routes, which the manual covers.
* `kit.session(tenant, principal)` opened a session on that database, on Ada's behalf.
* The `Mapper` turned the `Book` into triples, and the `UnitOfWork` sent them in one transaction,
  in the book's own named graph, with a version token.
* `get` read the graph back and the mapper rebuilt the `Book`.
