== Purpose and origin

*Built for* giving Django-era Python web developers an ORM-like experience over Neo4j: class-declared nodes, a `.nodes` query manager, relationships as managers, Django integration (`django_neomodel`).
Robin Edwards started it in 2013 (`LICENSE`, `pyproject.toml`). It lives in the *neo4j-contrib* community organisation, not maintained by Neo4j, Inc. as a product; 15 contributors listed in `AUTHORS.txt` (GitHub shows more), maintainers Marius Conjeaud, Antoine Nguyen and Athanasios Anastasiou; strict semver since 6.0.

*Design angle.* Developer-experience-first and store-specific: Active Record over the official driver, with async/sync parity.

*Where it fits.* Nowhere as a component: it is a labelled property graph with Cypher only, not RDF.
As a design benchmark it shapes the rdf-persistence L1 API (declaration, query sets, transactions, errors) and the L2 transaction ergonomics.
It passes DEC-5 (1.1k stars, active), but its store is out of scope, so ideas only.

== How it works

*Declaration.* Classes subclass `StructuredNode`; `Property` descriptors and `RelationshipTo/From/Relationship` are class attributes gathered by the `NodeMeta` metaclass (`async_/node.py:25, 36-125`).
`Property[V]` is generic with `required`, `unique_index`, `index`, `fulltext_index`, `vector_index`, `default`, `db_property`, and `inflate/deflate` (`properties.py:91, 223-242`).
Labels are the class name plus every ancestor; a registry resolves a label set to the most specific class on read (`node.py:730`, `_node_class_registry.py`).

*Identity.* `__eq__`/`__hash__` compare the database `element_id`; unsaved nodes compare by object identity (`node.py:171-200`). `UniqueIdProperty` gives uuid4 keys. *No identity map.*

*Save.* Active Record. `save()` issues `MATCH … SET` with parameters and escaped keys, or `UNWIND … CREATE` (`node.py:801-845`). It SETs all defined properties every time (no dirty tracking).
`get_or_create` / `create_or_update` use `MERGE` (`node.py:241`); `bulk_create` is one `UNWIND` query; `bulk_save` takes at most two round-trips.

*Relationships.* Lazy managers (`connect`, `disconnect`, `reconnect`, `replace`; `relationship_manager.py:128-364`). Eager loading is explicit through `traverse('a__b')`, `Path(optional=True)` and `resolve_subgraph()`.
Cardinality (`One`, `ZeroOrOne`, `OneOrMore`) is checked *client-side* on connect with a pre-count (`cardinality.py:122-135`). `StructuredRel` gives edges with properties.

*Querying.* `Person.nodes` returns a lazy, generic-typed `NodeSet[Person]` with Django lookups (`filter(age__gt=3, lives_in__name="X")`) and `Q` objects (`match.py:1650`, `match_q.py:165`).
A `QueryAST` of string fragments is rendered to Cypher (`match.py:520, 575`). The escape hatch `db.cypher_query(q, params, resolve_objects=True)` maps raw results back to models (`query.py:242`).

*Transactions.* `db.transaction`, `read_transaction`, `write_transaction`, each a context manager, decorator or `begin/commit/rollback`, with timeouts and bookmarks (`transaction.py:19-140`). State lives in `ContextVar`s (`connection.py:124-136`).

*Async and sync.* Async is the source; `bin/make-unasync` generates the sync API.

*Schema and bridge.* `install_all_labels()` / CLI create constraints and indexes, never implicitly (`schema.py:170-203`). `PydanticBridge` exports pydantic models and JSON Schema (`contrib/pydantic.py:159-282`); relationship expansion is not done yet, as the changelog says.

== What to borrow

Each idea with its RDF translation:

* *Declare once, in the class body* → read the declaration from LinkML-generated pydantic slot metadata instead of Active Record classes.
* *Manager on the class* (`Person.nodes` → lazy, generic `NodeSet[T]`) → `Repository[T].query().filter(...)` compiled to SPARQL SELECT wrapped by CONSTRUCT.
* *Kwargs lookups across relationships* and `Q` objects → SPARQL FILTERs and property paths.
* *`traverse()` / `Path(optional=True)`* → property paths and OPTIONAL blocks for eager loading.
* *QueryAST → renderer split* → an AST (or `sparql-grammar`, see xref:architecture/soa/libraries/prez.adoc[Prez]) rendered to SPARQL.
* *`cypher_query(resolve_objects=True)`* → raw CONSTRUCT → mapper → objects.
* *One transaction object, three styles* (context manager, decorator, manual) with read/write variants and ContextVar scope → `with session.begin()` / `@transactional`; a real transaction on local stores, one atomic Update request on remote ones.
* *Label inheritance plus registry* → `rdf:type` set from `is_a`, resolved to the most specific class.
* *Cardinality classes* → LinkML `required`/`multivalued`, checked on save or by SHACL.
* *Explicit `install_labels` CLI* → `install-shapes` emitting SHACL from LinkML.
* *Per-class exceptions* (`Person.DoesNotExist`, `node.py:39-41`) and model-aware error messages (`exceptions.py:117, 196`).
* *Async-first with generated sync* (unasync).
* *Slow-query log* with timing and redacted parameters (`async_/query.py:81-115`); it logs only when `config.cypher_debug` is on and the query exceeds `slow_queries` (`query.py:107-108`).

== What to avoid

* *Active Record:* conflicts with a persistence-free domain and cosmic-python layering.
* *No identity map:* the same node fetched twice gives two objects; the last `save()` wins.
* *Save rewrites all properties* (no dirty tracking).
* *Client-side read-then-write cardinality checks* race under concurrency.
* *Lazy relationships invite N+1* unless `traverse()` is used.
* *A global `db` singleton* with module config makes DI and test isolation awkward; tests need a live Neo4j.
* *Hooks as a security boundary:* they are bypassed by raw Cypher, `lazy` bulk creation, and `get_or_create`/`create_or_update` (no `post_create`); `bulk_create` skips `pre_save`/`post_save`.
* *API churn:* 7.0 moved bulk operations and changed `match()`; keep our public surface small from day one.

== Authorization seams

* *No ACL concept.* Everything runs as the connection user.
* *One seam: identity propagation.* `db.impersonate(user=…)` puts the user in a ContextVar and attaches it to each query (`transaction.py:117`, `connection.py:133`). Neo4j Enterprise RBAC then enforces per label, relationship type and property, server-side. Enterprise-only.
* *Hooks* (`pre_save`, `pre_delete`) could call a PDP, but they are not a reliable PEP. A repository wrapper over `NodeSet` is the natural application-level PEP.
* *Lesson for DEC-8:* "forward the end-user identity to a store or proxy that enforces policy natively". The RDF analogues are GraphDB or Stardog RBAC, Virtuoso graph security, or an authorizing SPARQL proxy given the user's JWT. The persistence layer only carries the identity in a ContextVar.

== Code-generation fit

* LinkML has no neomodel generator; a custom Jinja one is about 200 LOC (class → `StructuredNode`, scalar slot → `Property`, `identifier` → `unique_index`, enum → `choices`, object slot → `RelationshipTo` with cardinality, `inverse` → `RelationshipFrom`).
* *Better for us:* keep the domain as LinkML `gen-pydantic` classes and offer a neomodel-*like* API as a separate persistence layer that reads `slot_uri`, `range`, `multivalued`, `inverse` at runtime.
* *Fit:* medium-high for the API ideas, low for reusing the code.

== Final verdict

*Ideas.*

. neomodel is the *developer-experience benchmark*: declare once, a lazy generic `Model.nodes` query set with `field__op` lookups and `Q`, one transaction object usable three ways, per-model `DoesNotExist`, async-first with a generated sync API, and typing regression tests. Copy the *API shape*, reading the mapping from LinkML metadata.
. *Do not copy its core:* Active Record (persistence inside domain classes), no identity map, no unit of work, save rewrites every property, and client-side cardinality checks that race.
. Its one authorization lesson, *forward the end-user identity to a store that enforces policy* (`db.impersonate`), carries over directly to RDF stores and proxies (AZ19). Any policy in hooks is bypassable.
