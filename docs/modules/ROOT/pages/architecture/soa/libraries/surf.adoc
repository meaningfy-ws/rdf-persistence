== Purpose and origin

*Built for* treating RDF resources on any triple store as Python objects without declaring a model, in the style of Ruby's ActiveRDF.
It came out of the DERI / NUI Galway Semantic Web research context around 2009; authors Cosmin Basca (licence header, `setup.py`) and Peteris Caune (`resource/lazy.py`).
Last release 2016, last commit 2017; the GitHub repo is not archived.

*Design angle.* Schema-less exploration of Linked Data (DBpedia and FOAF examples); store plugins first, so the same code runs against rdflib, Sesame, Allegro or Virtuoso; convenience over correctness (Active Record, lazy attributes, SPARUL 1.0).

*Where it fits.* L1 and L2 ideas only: the reader/writer store split, one-query eager loading, inverse navigation.
It does not fit L0 (no model, against LinkML-first), L3 (no principal) or L4–L6, and no variant as a dependency (Python 2, fails DEC-5).

== How it works

*Mapping.* None ahead of time. `Session.map_type(uri)` builds a class with `type(name, (Resource, *mixins), …)` (`session.py:245-266`).
`session.mapping = {type_iri: Mixin}` adds behaviour per RDF type.
`attr2rdf("foaf_name")` resolves attribute names through a global namespace registry (`util.py:140`); `is_foaf_knows_of` navigates inverse arcs.

*Identity.* A resource is its subject IRI; `__eq__` and `__hash__` use `subject` (`resource/__init__.py:896-908`).
Missing subjects get a UUID IRI (`uuid_subject`, `util.py:239`).
There is *no identity map*: every load builds a new instance (TODO at `resource/__init__.py:461`).

*Lazy loading.* `__getattr__` returns a `LazyResourceLoader` that runs one SPARQL query per attribute (N+1).
Counter-measures: `load()` fetches all direct and inverse triples; `ResultProxy.full()` eager-loads in one query (a sub-select plus a UNION of direct and inverse triples, with no `VALUES`, `plugin/query_reader.py:299-330`) only when the reader has `use_subqueries=True`, which is off by default; otherwise it runs 1 + 2N queries (`:202-206, 236-239, 270-297`). The VALUES + UNION variant is xref:architecture/soa/libraries/oldman.adoc[OldMan]'s.

*Dirty tracking and commit.* One boolean per resource in a *class-level global set* `Resource._dirty_instances` (`resource/__init__.py:169, 225-242`), shared by every session.
`Session.commit()` loops over that set and calls `update()` (`session.py:351-357`): no atomicity, rollback or ordering.
*Bug:* reading an unloaded attribute sets `dirty = False` (`resource/__init__.py:517`), so a pending edit is silently dropped.

*Writes.* Replace strategies, not diffs: `save()` deletes every triple of the subject then inserts; `update()` deletes `(s, p, *)` per held predicate then inserts (`plugin/sparql_protocol/writer.py:154-166`).
The SPARQL writer emits *SPARUL 1.0 / Virtuoso syntax*: `INSERT INTO <g>`, `DELETE FROM <g>`, `OR`/`AND` in filters (`writer.py:90, 119`; `translator/sparul.py:84, 101`). None of it is SPARQL 1.1 Update.
Delete and insert go as two HTTP requests unless `combine_queries` joins them, per context group, with `\n` instead of `;` (`writer.py:189-196`); that combined request is not valid SPARQL 1.1, so single-request atomicity (T1) is only partial.

*Named graphs.* Each resource has a `context`; the SPARQL writer groups by context, the rdflib writer ignores it (`plugin/rdflib/writer.py:128`).

*Querying.* `Class.all()` and `get_by(foaf_name=…)` return a lazy, chainable `ResultProxy` (`get_by/filter/order/limit/offset/full`).
`.filter(foaf_age="(%s > 15)")` pastes raw SPARQL. A fluent `surf.query` AST is translated to strings. Raw SPARQL results are not mapped to objects.

*Stores.* `Store(reader=…, writer=…)` pairs plugins (rdflib, SPARQL protocol, Allegro, Sesame2) found by entry points (`store.py:66-87`, `plugin/manager.py`).

*Serialisation.* rdflib formats; its "JSON" is RDF/JSON (Talis), not JSON-LD (`serializer.py:46`).

== What to borrow

* A *reader/writer split in the store port*: read from a replica or endpoint, write elsewhere (`Store(reader=, writer=)`), plus Null Object stores (`NoneReader`, `NoneWriter`), borrowed only as explicit test fakes: a missing or read-only writer must fail loudly (T7, T13).
* A *lazy, chainable query object* with `first()` / `one()` semantics (`NoResultFound` / `MultipleResultsFound` style) and an explicit eager `full()` mode (one query only with `use_subqueries=True`, default off; otherwise 1 + 2N queries). Make one-query eager loading the default.
* *Inverse-arc navigation* as a first-class concept (`is_x_of`).
* *Grouping writes by named graph* before emitting updates (`_group_by_context`).
* A *decorating reader/writer plugin* as a cheap PEP seam.

== What to avoid

* *A silent default writer*: a `Store` without a writer gets `NoneWriter`, whose methods all `pass` (`store.py:80-83`, `plugin/writer.py:193-213`), so saves vanish without an error.
* *Global dirty state that reads clear* (`resource/__init__.py:169, 517`): silent lost updates. Dirty state must be per session and per attribute.
* *No identity map*: one IRI loaded twice gives two diverging objects.
* *Replace-all updates* that wipe triples the object never loaded, sent as two non-atomic requests.
* *Dialect lock-in* to SPARUL 1.0 / Virtuoso.
* *String-built SPARQL with user fragments* (`filter(foaf_name="(%s LIKE 'J%%')")`): injection risk.
* *`__getattr__` magic*: no typing, and a typo like `p.foaf_nmae` silently becomes a new predicate.
* *Plugins that disagree*: the rdflib writer ignores named graphs.
* *Docs that promise what code lacks.* The session cache ("keeps a cache of already loaded data") is *claimed, not found in code* (`session.py:70` `# TODO: add cache`). `auto_persist` is *claimed, not found in code* (`resource/__init__.py:380`).

== Authorization seams

* No authorization concept: no principal, request context or read-only fields.
* *PEP location:* the `Store` facade is the single choke point for every read and write (`store.py:120-235`). A decorating reader/writer plugin could filter or block calls. Raw `execute_sparql` bypasses object-level checks, so the PEP must sit at or below the store.
* *Behind an authorizing SPARQL proxy:* poor fit. SPARUL 1.0 writes are rejected by SPARQL 1.1 parsers; explicit `GRAPH` / `FROM` clauses clash with proxies that own graph placement. Only context-free reads would work.
* *Verdict:* nothing to borrow except the plugin-decorator PEP idea.

== Code-generation fit

*None.* There is no model input, so LinkML output has nowhere to plug in.
The nearest analogue is `session.mapping`, which could take generated mixins per `class_uri`, losing types and validation.

== Final verdict

*Ideas.* No code: Python 2, SPARUL 1.0 dialect, fails DEC-5.

. A store port with *separate reader and writer* is cheap and useful (replicas, V5, PEP decorators), but a missing writer must *fail loudly, never no-op*.
. *Dirty state must be per session and per attribute.* SuRF's process-global dirty set, cleared by reads, is the canonical lost-update bug.
. *One-query eager loading must be the default, not an opt-in flag*; otherwise N+1 is what developers get.

AZ19 static credentials per writer, T1 combined request (invalid `\n` separator), T3 Sesame2 `x-rdftransaction`, D11 store errors with query text, S18 `load_triples` separate from object writes (all partial); AZ22 n.a. (no client cache).
As expected for a 2009–2017 Active Record ORM, the v3 areas (authorization, generation, transactions, events, UI) postdate it.

Aggregates (`count`, `min`, `max`, `avg`) exist only through the raw `select()` builder (`query/__init__.py:120-152`); `ResultProxy` has no count, so Q15 stays partial.

Notable absences: I3 identity map, P4/P13 transactions, M5 validation, X1 JSON-LD, Q6 injection-safe binding, D1 typing.

Proposed by this report: AZ1 PEP as a store-port decorator (a seam only in SuRF; AZ1 is absent). No round-4 or round-5 proposals.

Round-5 v4 partials: B10 named graph per resource, PG1 query AST with translators, T14 several stores per session (no atomicity), D17 query object renders to SPARQL, D22 class lookup by name or URI. T13 is inverted: the silent `NoneWriter` swallows writes.
