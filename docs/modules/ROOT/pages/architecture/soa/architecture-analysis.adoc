*Constraints found by the review.* One SPARQL Update request is the only portable atomic unit,
and a failed guard skips only its own operation, so a commit must be *one* operation joining
every guard and carrying the outbox and new owned children, confirmed by an ASK (on the primary) for an append-only commit record unique to this commit — not a "last transaction" marker, which a later writer would overwrite. New aggregates need a creation guard. On-disk Oxigraph does not serialise guarded updates, so its adapter needs a write lock. Blank nodes cannot be deleted by template,
so owned children need IRIs. LinkML has no composition construct. Graph level is the only
portable authorization granularity. No Python object–RDF mapper, RDF migration runner or LinkML
schema diff passes the reuse threshold or exists at all. Licences to check: Fluree BUSL-1.1,
Zitadel AGPL-3.0.

*Unknowns that would normally be drivers:* scale, latency budget, availability target, whether
graph-level authorization is enough, and whether the UI will ever send free SPARQL.

=== Commit an aggregate

One update operation carries every version guard, the data, the outbox
records, the new owned children and an append-only commit record; an ASK for that record on the primary tells *committed* from *conflict*. Transactional stores and Fluree's commit receipt make the ASK unnecessary.

[mermaid]
....
sequenceDiagram
  autonumber
  participant App as Application code
  participant AS as Aggregate Session
  participant CSC as Change Set Compiler
  participant PEP as Policy Enforcement Port
  participant SP as Store Port
  participant TS as Triple Store
  App->>AS: commit()
  AS->>CSC: compile(diff, versions, events)
  CSC-->>AS: change set: guards v=n and creation guards, children, outbox, commit record T
  AS->>PEP: check(change set, identity)
  alt permitted
    AS->>SP: execute(change set)
    opt store does not serialise guarded updates
      SP->>SP: take adapter write lock
    end
    SP->>TS: DELETE INSERT WHERE all guards (one operation)
    SP->>TS: ASK commit record T on the primary
    alt commit record present
      SP-->>AS: committed v=n+1
      AS-->>App: ok, events dispatched after commit
    else commit record absent
      SP-->>AS: ConcurrencyConflict
      AS-->>App: ConcurrencyConflict, reload and re-apply
    end
  else denied
    AS-->>App: PermissionDenied, no store call
  end
....

The reuse list is wider than xref:architecture/soa/build-vs-reuse.adoc[build versus reuse]: it
also names alternatives (Cerbos, SpiceDB, QLever, Virtuoso, SPARQLWrapper, Strawberry or
Ariadne), not only the recommended pick per layer. Reuse threshold (DEC-5): more than 200 GitHub
stars and a commit within 12 months; components below it are marked.

Nothing at the level of the RDF model, parser, store, SPARQL client, identity provider, policy
engine, test framework or JavaScript data layer is built.
