# Design: documentation improvements

Nav order and labels follow the EPIC's outline. Every page in `pages/` stays in the nav (the
existing check).

## How the split is done (DEC-2)

A one-off script in `temp/` reads `howto/adopt.adoc`, cuts it at its `== N.` headings into the
pages above (an `[#id]` line right before a heading travels with that heading), gives each page a
`= Title` (the step's heading without its number) and `:description:`, and keeps
`:page-revised: 2026-11-10 by the developer` on every page cut from the revised one. It then
rewrites links:

- inside a moved page, `<<id>>` / `<<id,text>>` whose id is now on another page becomes
  `xref:user-manual/<page>.adoc#id[text]` (text defaulting to the target section's title);
- in every other page and the nav, `xref:howto/adopt.adoc#id[...]` becomes the page holding `id`;
  a bare `xref:howto/adopt.adoc[...]` becomes `xref:user-manual/index.adoc[...]`;
- `xref:howto/commits.adoc` becomes `xref:architecture/commits.adoc`.

The script is not committed (a one-off move); the link check (DEC-7) proves the result.

## The link check (DEC-7)

`check_links()` in `docs/tools/check_docs.py`:

1. Index every page: its path, its aliases, and its ids: `[#id]`, `[[id]]`, `anchor:id[]`, `[id=x]`
   attributes, and each section title's implicit id: lower-case, characters other than word
   characters, spaces, dots and hyphens dropped, runs of spaces, dots and hyphens replaced by the
   separator, with `-2`, `-3` suffixes for repeats. Prefix and separator are read from
   `antora-playbook.yml` (`idprefix: ''`, `idseparator: '-'`); a first draft assumed Asciidoctor's
   defaults (`_`) and reported 23 false breaks on develop, which is how the reading was found
   necessary. Inline formatting (`` ` ``, `*`, `_`) is stripped from the title first. A section
   with an explicit id has no implicit one.
2. For each `xref:target.adoc[#frag]` (in pages and nav), resolve `target` relative to the pages
   root (`ROOT:` and module-less forms), fail if no page or alias matches, fail if `frag` is given
   and not among the target's ids.
3. For each `<<id>>` / `<<id,text>>`, fail if `id` is not among its own page's ids; a
   `<<page.adoc#id>>` form is treated as an xref.

Background pages are checked too (a broken link is broken anywhere).

## The reference generator (DEC-6)

`docs/tools/reference.py` writes two partials:

- `partials/public-api.adoc`: a table of `rdf_persistence.__all__`, one row per name, sorted, with
  its kind (class, function, constant) and the first sentence of its docstring (empty when none);
  the testkit's `__all__` in a second table.
- `partials/rp-generate-usage.adoc`: the CLI's `--help` text in a listing block, taken from the
  argument parser in `rdf_persistence_generation/cli.py` (`COLUMNS=100`).

`reference.py --check` exits 1 when either file would change; `check_docs.py` calls it.
`make docs-reference` rewrites them.

## The tutorial (DEC-3)

`tutorials/getting-started.adoc` walks: install, the one-class model (included by tag), generate,
the code that stores and reads a note (included by tag), run it, what happened, where to go next
(user manual pages). The example's test lives in `tests/generator/integration/`, the tier that
already runs `rp-generate` without containers, so CI runs it in `make test-generator`.

## Use cases (DEC-4)

Actors (developer, Q-8): **application developer** (models a domain, builds and runs an app with
the toolkit), **API client** (the app's front end or another system calling the generated
service), **system architect** (reuses the toolkit as the data layer of a platform of their own),
**toolkit developer** (changes the toolkit). Use cases are at user-goal
level, Cockburn style, one line each: goal, primary actor, capabilities, page. Ids `UC-1..`.

## Examples

- A link `xref:howto/adopt.adoc#tenancy[step 9]` in `howto/dump-restore.adoc` becomes
  `xref:user-manual/tenants.adoc#tenancy[step 9]`. Link text that says "step N" is left as is
  (DEC-2: no prose rewrite), since the user manual index keeps the step numbers in its list.
- `<<guard>>` in `user-manual/generate.adoc` becomes
  `xref:user-manual/generated-classes.adoc#guard[Guard the model in your tests]`.

## Error matrix

| Situation | What happens | Handling |
|---|---|---|
| A section id computed differently from Asciidoctor | false "missing anchor" | unit tests of the id function with titles containing backticks, digits, punctuation; compare with the built site for a sample |
| An `[#id]` line placed above a block, not a heading, at a cut point | the anchor ends up on the wrong page | the cut keeps a preceding `[#id]` only when the next non-blank line is a `==` heading |
| An xref with an attribute in its target (`{page}`) | unresolvable statically | skip targets containing `{`; none exist today |
| A cross-component or external link | not ours to check | only `.adoc` targets without a component prefix other than `ROOT:` are checked |
| The diagrams of the metamodel fail `check-diagrams` | site shows raw text | DEC-5 fallback: link the schemas, drop the include |
| `reference.py` imports `rdf_persistence` and the import has side effects | slow or failing check | it imports only the package and reads `__all__`; the CLI parser is built without running |

## Anti-patterns

- Restating a SHALL from `openspec/specs/` in a page (two truths).
- A how-to that explains; an explanation that instructs. Move it, do not mix it.
- A page reachable only by search (the nav check stops it).

## Risks / Trade-offs

- **RISK-1** (likely, low): outside links to `howto/adopt.adoc#anchor` (the consumer's repository,
  issues) land on the user manual index without the anchor. Accepted; the index lists every step.
- **RISK-2** (possible, medium): in-flight branches edit `howto/adopt.adoc`; their merge conflicts
  with the deletion. Mitigation: the PR description names the mapping, and the change is one PR
  merged quickly.
- **RISK-3** (possible, low): the generated API table is noisy (141 rows). Accepted: it is a
  look-up page; the user manual stays the way in.
- **RISK-4** (possible, medium): the example app breaks on a later API change. That is the point:
  its test fails in CI, and the tutorial is fixed with the code.

## Test plan

- The link check and the freshness check: `tests/unit/test_check_docs.py`, where `check_docs.py`
  is tested today (fixture pages in `tmp_path`).
- The example: `tests/generator/integration/test_getting_started_example.py`.
- Acceptance: `make check-docs`, `make check-diagrams`, `make build-docs` with no Antora warning,
  `make test-changed check-quality`.
