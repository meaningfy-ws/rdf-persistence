## Summary

pydantic-rdf is a thin **Pydantic v2 ↔ rdflib Graph codec**:
- `BaseRdfModel` adds a required `uri` field and class-level `rdf_type` / `_rdf_namespace`.
- Predicates default to `namespace[field_name]` and can be overridden with
  `Annotated[..., WithPredicate(iri)]`.
- `model_dump_rdf()` emits a new Graph; `parse_graph(graph, uri)` and `all_entities(graph)`
  hydrate validated models.

There is no store, no query, no update and no session; the library stops at the Graph boundary.
Its value is that the domain model *is* a Pydantic model, so validation and JSON Schema / FastAPI
interop come for free. The code is small and clean, but it has notable gaps around literals.
**Inactive since May 2025.**

## Architecture (GitNexus + source)

- **One class does everything:** `BaseRdfModel` (`src/pydantic_rdf/model.py:40-389`). Its
  methods group into:
  - type-analysis helpers: `_get_annotated_type`, `_get_union_type`, `_get_sequence_type`,
    `_get_item_type`, `_resolve_type_info` (model.py:63-138);
  - field extraction: `_extract_model_type`, `_convert_rdf_value`, `_extract_field_value`
    (model.py:141-245);
  - parsing: `parse_graph`, `all_entities` (model.py:248-322);
  - serialisation: `model_dump_rdf` (model.py:325-389).
- **Supporting modules:**
  - `annotation.py`: `WithPredicate`, `WithDataType` marker dataclasses.
  - `types.py`: `PydanticURIRef`, an `Annotated[URIRef, URIRefHandler]` with a core schema that
    coerces str → URIRef and emits JSON Schema `{"type":"string","format":"uri"}`
    (types.py:24-62).
- **Execution flows:** every GitNexus process converges on `_resolve_type_info` /
  `_get_*_type`. Annotation introspection is the core mechanism. Flow:
  `parse_graph → _extract_field_value → graph.objects → _convert_rdf_value → (nested parse_graph | Literal.toPython) → model_validate`.

## Implementation principles

- **Mapping.**
  - Field → predicate: `WithPredicate.extract(field)` or `cls._rdf_namespace[field_name]`
    (model.py:53-61).
  - Type → rdf:type: the `rdf_type` ClassVar, checked strictly on parse; parse raises
    `ValueError` if `(uri, rdf:type, rdf_type)` is absent (model.py:283-284).
  - Inheritance: no subclass/polymorphic dispatch; `all_entities` matches the exact `rdf_type`
    only (model.py:320-322).
- **Identity.** `uri: PydanticURIRef` is a required field (model.py:49). There is no minting and
  no blank-node support: nested values must be `URIRef` to recurse (model.py:188), and
  `all_entities` skips BNodes (model.py:321). Parsing uses a `(cls, uri)` → instance cache with
  an `_IN_PROGRESS` sentinel (model.py:270-299). This is a per-call identity map plus cycle
  detection, but on a cycle it **raises** `CircularReferenceError` instead of resolving it
  (model.py:192-193, 275-276; test `tests/test_deserialize.py:308-327`).
- **Relationships.** A nested `BaseRdfModel` field (or `Self`) is a reference: `uri` is emitted
  and the child graph is merged in (model.py:376-380). `list[Model]` gives 1-n (model.py:363-369).
  Ordering is not preserved (multiple triples; no rdf:List). There is no inverse, loading is eager
  only, and serialisation always cascades the whole reachable object tree.
- **Literals.**
  - Serialisation uses a bare `Literal(value)` (model.py:373, 387), so rdflib infers the datatype
    from the Python type.
  - `dict` fields become a JSON string literal (model.py:383-385).
  - Parse uses `Literal.toPython()` (model.py:199). **Language tags are dropped on read and
    cannot be written.**
  - **`WithDataType` is exported and documented but never consumed** (grep: used only in
    `__init__.py` and its own definition, `annotation.py:41-60`).
- **Persistence and update.** None. `model_dump_rdf()` builds a new Graph each call (model.py:336).
  Storage is the caller's `graph += ...`.
- **Querying.** None built in. `examples/sparql_integration.py` shows the pattern: the user runs
  `g.query(SELECT ?s ...)`, then calls `Model.parse_graph(g, row.s)`.
- **Validation.** Pydantic validation on construct and on parse (`model_validate`,
  model.py:296), which also works as an M5 "validate on load". There is no SHACL.
- **Schema export.** Pydantic JSON Schema with URIs typed as `format: uri` (types.py:42-47;
  `tests/test_schema.py`).

### Proposed new features

- **M6 Convention-based predicate derivation**: default predicate = class namespace + field name,
  with per-field override. Evidence: model.py:53-61.

## JS-friendliness

Indirect only. The models are Pydantic, so they produce JSON Schema (with `format: uri` for IRIs)
and plug straight into FastAPI/OpenAPI. There is no JSON-LD `@context` generation and no TS types.

## Reuse verdict for rdf-persistence: **borrow ideas** (optionally vendor the `PydanticURIRef` idea)

- **Borrow:**
  - `Annotated[...]` markers for predicate and datatype metadata (and actually honour the
    datatype).
  - Namespace-plus-field-name predicate defaults.
  - The `PydanticURIRef` core-schema type.
  - The `(cls, uri)` hydration cache.
- **Do not depend on it:**
  - Single maintainer, inactive since 2025-05.
  - Mapping lives on a required base class, which conflicts with keeping LinkML-generated domain
    classes persistence-free (cosmic-python Data Mapper). rdf-persistence should hold the mapping
    in an external mapper or registry keyed by LinkML `class_uri`/`slot_uri`, not on `BaseModel`
    subclasses.
  - It covers none of the persistence, query or store scope.

## Risks / anti-patterns observed

- **Silently ignored public API**: `WithDataType` is exported and documented but never read
  (annotation.py:41).
- **Cycles fail hard on read** (`CircularReferenceError`) despite the "circular references
  supported" claim. On write, `model_dump()` of a cyclic object graph would recurse (not
  verified by running).
- **Language tags are lost** on round-trip; `dict` is stored as a JSON-string literal, which is
  opaque to SPARQL.
- **Unordered multi-values**: `list[T]` is serialised as repeated triples, so the list order is
  not guaranteed on read.
- **Global type coupling**: `model_config = arbitrary_types_allowed=True` is set on every
  subclass (model.py:43).

### (b) Developer experience deep-dive

- **Shortest complete example.** README "Quick Example", **14 non-comment lines**: model with a
  custom predicate, serialise, deserialise.
- **Concepts to learn: about 5.** `BaseRdfModel`; `rdf_type`; `_rdf_namespace`; the required
  `uri`; `WithPredicate` (plus the inert `WithDataType`). The API is `model_dump_rdf`,
  `parse_graph` and `all_entities`. Everything else is plain Pydantic.
- **Typing and IDE.** Excellent. Fields are ordinary Pydantic annotations, `parse_graph` returns
  `T`, and the API is `Self`-typed. A mypy and ruff config is shipped.
- **Real error messages.**
  - `ValueError: URI http://example.org/x does not have type http://example.org/Person`
    (model.py:284). Clear.
  - `CircularReferenceError: Circular reference detected for http://example.org/node1`
    (exceptions.py:8). Clear, but it reports a limitation rather than a user error.
  - Missing required data surfaces as a normal Pydantic `ValidationError` from `model_validate`
    (model.py:296), which developers already know how to read.
- **Docs.** A short quick start plus an API reference generated from docstrings; no conceptual
  or how-to depth. There is a small doc bug: `from pydantic import Annotated`.
- **Footguns.**
  - `WithDataType` is silently ignored.
  - Language tags are lost on round-trip.
  - Cyclic data raises instead of loading.
  - A single-valued field silently takes the first of several values.
  - `dict` fields are stored as JSON-string literals.
  - `_rdf_namespace` is a private-looking name that the user must set.
- **What developers would love:** "it's just Pydantic" — FastAPI, JSON Schema and validation
  for free. **What they would hate:** the silent data loss (language tags, extra values,
  datatype) and the lack of any store or query layer.
- **DX score: 3/5.** The happy path is excellent, but silent data loss costs two points.

### (c) Authorization seams

- **Fully ACL-agnostic by construction.** The library never touches a store. The caller fetches
  a Graph (for example a CONSTRUCT through an authorizing proxy) and hands it to `parse_graph`,
  so whatever the proxy filtered is what gets hydrated.
- **PEP sites, if needed:**
  - Before the call: where the caller obtains the Graph (query-level or graph-level).
  - Field-level (A3): Pydantic serialisation options (`exclude`, `Field(exclude=True)`, custom
    serialisers) at the API boundary. pydantic-rdf itself adds nothing for this.
  - Write side: a PEP could check the triples from `model_dump_rdf()` before the caller sends
    them, because the full set of triples is available in the returned Graph.
- **Verdict:** clean seam by absence. This is the right shape for a codec in rdf-persistence:
  the codec stays policy-free and enforcement sits in the store port or proxy.

### (d) Layer coverage and codegen fit

- **Layers:**
  - L1 partial: an object↔Graph codec, with no repository or unit of work.
  - L0 indirect: models are Pydantic, and JSON Schema export covers X4.
  - L4/L5 indirect: through FastAPI/OpenAPI, because the models are Pydantic.
  - L2, L3, L6: none.
- **LinkML fit: good, with template work.** `gen-pydantic` already emits Pydantic v2 classes.
  To make them pydantic-rdf models, the generator would need to:
  1. Change the base class from `ConfiguredBaseModel` to `BaseRdfModel` (via a custom template
     directory).
  2. Emit `rdf_type = <class_uri>` and `_rdf_namespace = <default_prefix>`.
  3. Emit `Annotated[..., WithPredicate(<slot_uri>)]` for each slot.
  4. Map the LinkML `identifier` slot (usually `id`) to the mandatory `uri` field.
  Several LinkML features would still not be honoured:
  - `is_a` inheritance (no rdf:type subclass dispatch);
  - `range: langString` and datatype ranges (inert `WithDataType`);
  - `inlined` versus reference semantics (everything is a reference plus a cascade);
  - `multivalued` + `list_elements_ordered` (no rdf:List).
  Newer gen-pydantic versions can attach `linkml_meta` with class and slot URIs. A generic
  external mapper could read that instead of a base class. **Not verified here.**

### (b) Purpose and origin

- **Built for:** letting Pydantic v2 users load and dump RDF with the model they already have.
  The README promises "seamless bidirectional conversion between typed data models and semantic
  web data".
- **Who and when:** one author ("Omegaice"), 2025. Two releases (0.1.0, 0.2.0 on 2025-05-02),
  then dormant. No institutional context is stated.
- **Design angle:** a codec, not an ORM. It deliberately stops at the `rdflib.Graph` boundary and
  lets Pydantic do validation and JSON Schema. The mapping sits on the model through a base class
  plus `Annotated` markers: an Active-Record-style coupling that is convenient for hand-written
  models.
- **Where it could fit:**
  - **L1, inside rdf-persistence, as a design donor for the Graph↔object codec.** Its
    conventions are worth reusing: namespace + field-name predicates (M7), `WithPredicate`, and
    `PydanticURIRef` (G5). Its base-class coupling is not.
  - With LinkML 1.10.0 `gen-pydantic` already emitting `linkml_meta` (class_uri, slot_uri) on
    persistence-free classes, our codec can read that metadata instead of requiring
    `BaseRdfModel`.
  - It fails DEC-5 (23 stars, no commit in 12 months), so it is ideas only, or vendoring under
    MIT.

### (d) Corrections to the integrated docs

1. **index.adoc:85-86 ("Mapping" pattern) lists pydantic-rdf as an example of "Mapping read from
   metadata, not written in domain classes … Domain classes stay persistence-free (Data
   Mapper)".**
   - That holds only for its `Annotated` markers.
   - pydantic-rdf itself requires every domain class to subclass `BaseRdfModel` and to declare
     `rdf_type` / `_rdf_namespace` ClassVars (model.py:40-49). The serialisation and parsing
     methods live on the domain class (model.py:249, 325). That is Active-Record-style coupling,
     not Data Mapper.
   - Suggest citing it for "`Annotated` field markers" only.
2. **libraries/pydantic-rdf.adoc:95, "`linkml_meta` … *not verified*".** Now verified against
   LinkML **1.10.0** (the `.venv` of this repo):
   - `gen-pydantic` defaults to `metadata_mode=auto` (pydanticgen.py:316, 939-940).
   - It emits `linkml_meta: ClassVar[LinkMLMeta]` per class (templates/class.py.jinja:14) and
     `json_schema_extra={"linkml_meta": …}` per field (templates/attribute.py.jinja:18).
   - `class_uri` and `slot_uri` are kept.
   - Caveat for approach A: `auto` mode **excludes** `range`, `inlined`, `inlined_as_list` and
     the template fields such as `multivalued` and the cardinalities (template.py:191, 260).
     A runtime mapper must infer those from the Python annotations, or the generator must run
     with `metadata_mode=full`.
   - Whether an *implicit* `class_uri` (derived from `default_prefix`) is materialised was not
     verified.
3. **catalogue.adoc (pydantic-rdf row), "silent data loss on unmapped fields".** This is
   imprecise. Ignoring unmapped predicates on parse is normal codec behaviour. The silent losses
   are elsewhere:
   - language tags (model.py:199);
   - extra values for single-valued fields (model.py:245);
   - the ignored `WithDataType` (annotation.py:41).

### (c) Final verdict and what to remember

**Verdict: ideas.** It is MIT and small enough to vendor the `PydanticURIRef` type; do not take
it as a dependency (fails DEC-5, dormant since 2025-05).

Three things a system architect must remember:
1. **Its base-class coupling is the wrong shape for approach A.** Read the mapping from LinkML
   `linkml_meta` on persistence-free generated classes instead.
   - LinkML 1.10.0 emits `class_uri` / `slot_uri` by default.
   - It drops `range`, `inlined` and `multivalued`, so generate with `metadata_mode=full` or
     infer those from the annotations (G33).
2. **Round-trip fidelity is the hard part a codec must get right, and pydantic-rdf does not.**
   Language tags, datatypes (`WithDataType` inert), extra values for single-valued fields, list
   order and cycles are all silently lost or fail. Our codec needs round-trip property tests on
   exactly these.
3. **"Policy-free codec" is the right authorization shape for L1.** The converter never touches
   a store, so enforcement lives in the store port or proxy and the codec stays ACL-agnostic.
