# Closure: overtaken by consumer practice (2026-11-27)

The developer closed this EPIC unbuilt on 2026-11-27 ("close it as overtaken"), after a review
of what changed since it was shaped on 2026-11-06. It is archived with `--skip-specs`: the
`rp-typescript-client` delta describes nothing built and is not merged into the truth.

## What the review found

- **The model half is delivered and has grown.** `rp-generate` writes TypeScript for every served
  schema, the domain and the service models, with imports between targets (#47, #371, #391).
- **The consumer settled the two-sources question.** MWB2 first typed its Web App from the
  OpenAPI document with `openapi-typescript` (the route of this EPIC's Q-2 answer), hit document
  defects (#54, #148, #153), and moved to LinkML-generated types for everything (#47); its rule is
  that no model type is hand-written. The developer confirmed the same rule on 2026-11-27: the
  client's models are generated from the model, no second source.
- **The calls half is the consumer's own.** Since 2026-11-09 MWB2 calls the API from its Next.js
  server (`server-only` adapters, about 430 lines and 860 lines of tests): bearer token, problem to
  a typed error, `ETag` to `If-Match`, the id from `Location`. Toolkit fixes it needed went in as
  issues (#300, #320). Browser-side hooks, stores and JSON-LD processing are not used.

## What stays live

- #402: every TypeScript target re-emits the toolkit's own TypeScript (a second copy of a type).
- #415: a consumer schema cannot extend `Problem`, so a consumer's typed problems cannot reach its
  OpenAPI and its TypeScript.

Both are shaped as their own change. A later EPIC that lifts the generic part of a consumer's HTTP
layer into the toolkit, or that reads JSON-LD in the browser (jsonld.js with the bundled generated
context, `safe: true`, per `background/soa/angles/jsclient.adoc`), is shaped only when a consumer
names the need (D-12).
